# Backup, migration, and sourced import research

Date: 2026-10-09. Research only. No builds, service changes, or qualification runs occurred.

## Authority and scope

The approved extras plan Task 9 requires actual SQL archives, fresh-destination restore, fenced migration, and bounded file/HTTP import. It also requires durable attribution, authorization, and unknown-outcome tests. A row summary or projection cannot satisfy this task.

This review uses published ROM commit `d7ef529040eec60dc869034c2d33130219db85fe`. Local unpublished `/root/ROM` source is not API authority. The inspected checkout is `/root/.cargo/git/checkouts/rom-93d40b828d518890/d7ef529`.

## Published archive contracts

`rom_backup::{read, write, Snapshot, Manifest, Collector, BackupLimits, MigrationPlan, ResourceMigration, migrate_snapshot, Stage, NativeOwnership, NativeAccess}` are public exports. [Public export list](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-backup/src/lib.rs).

`Backend` permits only `Sqlite` and `Redb`. Archive version is 6; storage format is 8. Default limits are 128 MiB and 400,000 aggregate records. `Snapshot` includes complete storage state, rows, receipts, events, effects, descriptors, and references. Its validation checks historical consistency and the live reference graph. [Model](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-backup/src/model.rs).

`write(path, backend, &snapshot, limits)` validates and stages publication. `read(path, backend, limits)` checks backend, versions, declared counts, size, and SHA-256. It rejects symlinks and non-files. Unix archive permissions must be exactly 0600. Non-Unix private archives are unsupported. External blobs and deliveries are excluded. [Archive implementation](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-backup/src/archive.rs).

The SHA-256 covers serialized header and body bytes. It does not authenticate their author. Do not describe this checksum as a signature, encryption, or hostile-tampering protection. SHA-256 is specified by [NIST FIPS 180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final). ROM explicitly limits its checksum claim to accidental corruption. [ROM security scope](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-backup/src/lib.rs).

`Sqlite::backup_to` collects one coherent transaction, including committed WAL data. `Sqlite::restore_from` requires a fresh destination. Restore validates, fences claims/cursors, rebuilds indexes, validates reconstruction, closes/syncs, and publishes. An uncertain post-publication reopen returns `Error::Unknown`. Redb has the corresponding methods. [SQLite maintenance](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-sqlite/src/maintenance.rs), [redb maintenance](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-redb/src/maintenance.rs).

## SQL gap and faithful candidate

Generic `rom::Storage` has bounded row/query/journal reads, receipts, atomic commits, and Work controls. It has no complete maintenance snapshot/export/restore interface. Public Resource reads cannot reconstruct all receipts, protected attribution, retry boundaries, effects, or frozen Work. [Storage contract](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/persistence.rs).

SQL adapters must own coherent transactional collection and fresh-database reconstruction. Two honest options exist: publish an upstream backend-neutral archive extension, or define an explicitly extras-owned SQL envelope. The latter can reuse public `Snapshot::validate` and `migrate_snapshot`, but cannot claim compatibility with ROM archive version 6. Passing `Backend::Sqlite` for PostgreSQL/MySQL data is invalid. This is a design candidate, not implemented support.

SQL collection must include every category in `Snapshot` and retain persisted storage limits. Restore must validate the complete graph and rebuild adapter indexes before cutover. Fence the destination and source owner throughout migration. Never infer coherent backup by concatenating independent `Storage` calls. Database-specific transactional and publication guarantees still require official engine documentation and native qualification.

## Published migration and canonical Work

`ResourceMigration::new::<Before, After>(fn(Before) -> Result<After>)` requires the same kind and exactly one version increment. `MigrationPlan::new` requires nonempty steps. `validate_work(fn(&PendingWork) -> Result<()>)` attests unfinished frozen contract compatibility; it cannot rewrite obligations. Callbacks must be pure and bounded; they are not sandboxed. [Migration plan](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-backup/src/migration_plan.rs).

`migrate_snapshot(snapshot, &plan, limits)` converts current and historical Resource values. It binds old receipt replay codecs, transforms frozen Work sources, and rebuilds references. Keys, Resource revisions, action inputs, and notification payloads are outside conversion. Every unfinished Work record requires the validator. Preserve the canonical ledger; do not create a maintenance-specific Work ledger. [Migration implementation](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-backup/src/migration.rs), [storage-state mapping](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/storage_state/maintenance.rs).

`StorageState::prepare_restore` fences old journal generation and Work claims while retaining identities, attempts, and outcomes. SQL restore can call this public method on its reconstructed state. It must persist the resulting state atomically. [State implementation](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/storage_state.rs).

Native `Sqlite::migrate_from` and `Redb::migrate_from` acquire source and fresh-destination ownership. SQLite accepts offline native formats 4 through 7 and current format. The interruption hook is gated behind `test-support`; do not treat it as ordinary application API. [SQLite migration](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-sqlite/src/migration.rs).

## Published sourced import seam

The published pin DOES export `SourceProvenance`, `SourceState`, `RevisionCondition`, `SourcePermit::trusted`, and `Runtime::{invoke_sourced, source_state, source_provenance}`. This seam requires no unpublished upstream API. `invoke_sourced` requires a Service actor and uses the ordinary mutation pipeline. Source ownership and target must match the registered definition. Authorization still applies. [Source contract](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/source.rs), [commit pipeline](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/execution/command.rs).

Provenance has `source`, `version`, nonzero `generation`, and `field_origins`. Source/version/origin labels are nonempty ASCII alphanumeric or `_.:-`, at most 128 bytes. There are at most 128 origins; field names are nonempty and at most 256 bytes. Keys are nonempty and at most 2048 bytes. Permit dependency revision and expiry must be nonzero. For a live value, origins must cover exactly its complete field set. Raw file paths, URLs, credentials, or arbitrary ETags are unsuitable labels. Derive safe opaque version labels instead. [Permit validation](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/source.rs).

The permit's `RevisionCondition` fences the managed source control Resource at commit. The Invocation's expected revision independently fences the target. Complete source-owned values fit this contract. Partial field ownership is not established by this API. Attribution is protected persistence metadata and requires separate metadata authorization. A metadata-only change is a durable revision. Exact replay creates no revision. [Consumer source tests](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/examples/consumer/tests/source_authority.rs).

`rom_config::ReloadTicket` demonstrates durable source activation, generation fencing, stable identity, and restart recovery. `request_with_epoch` and `resume_with_epoch` preserve an explicit original retry epoch. `SourceActivation` does not store that epoch; the caller must retain it. Default resume uses epoch zero. `apply` performs sourced Create/Replace; `delete` is explicit. Missing sources never imply deletion. Import actions can instead construct a normal action Invocation and invoke it through `invoke_sourced`, with complete output origins. [Ticket implementation](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-config/src/ingestion/ticket.rs).

Proposed imports need bounded records, bytes, parse depth, field sizes, and total duration. Prepare source generation before fetch/parse. Preserve the exact source identity, target revision, retry epoch, operation, and idempotency key for unknown-outcome recovery. Never turn `Error::Unknown` into confirmed failure or silently obtain a new identity. Imports must not write target tables directly.

For HTTP, use an explicit host endpoint and credentials, finite timeout, body bounds, and controlled redirect policy. Strong ETag comparison supports representation version checks; ETags are opaque validators, not origin authentication. `If-Match` uses strong comparison. A 304 is not a document body; 404 must not trigger implicit target deletion. These HTTP decisions follow [RFC 9110 validators](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.8) and [conditional requests](https://www.rfc-editor.org/rfc/rfc9110.html#section-13.1). ROM revision conditions remain necessary even when HTTP validators succeed.

## Required native qualification

- Each declared SQL profile: coherent backup under writes; restore into a new destination; existing-destination refusal; format/backend mismatch; checksum/size/count failure.
- Each SQL profile: interruption before publication, uncertain commit acknowledgement, source immutability, retry-epoch preservation, operator receipts, journal fencing, and pending Work validation.
- Migration: current/history/tombstone/protected attribution conversion, replay compatibility, references, frozen Work, malformed converter output, and callback failure.
- External objects: explicit exclusion or separate manifest; referenced-object existence and bounded digest verification; missing and modified object failure. Database archive success alone proves no object-store recovery.
- Imports: file plus real local HTTP/TLS service; malformed/oversized/truncated bodies, changed validators, stale generations, target conflict, repeated exact request, denied/revoked actors, unknown acknowledgement, and process-restart recovery.
- Verify accepted attribution through the public authorized metadata API after commit, backup, restore, and migration. Use an independent package consumer against the exact public pin.

## Remaining uncertainty

No SQL maintenance implementation was reviewed or executed here. Engine-specific snapshot isolation, DDL transactions, cutover ownership, and unknown acknowledgement must be researched per profile. No external-blob packaging format, authenticity scheme, resumable multi-record import policy, or production credential storage was selected. Source review establishes feasible public seams; it does not establish native support or completion.

## Follow-up: reusable ordinary action imports

`ReloadTicket` has no public action application method or public permit/Invocation accessor. Its private fields must not be recovered through serialized layout. Reuse public source primitives directly. The host must own managed generation preparation and authorization. The import helper can receive a host-approved `SourceProvenance`, `RevisionCondition`, target, expiry, and exact Invocation. It can construct `SourcePermit::trusted` without implementing another ticket controller. A private immutable prepared request can retain these public inputs for exact retry. [Ticket](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-config/src/ingestion/ticket.rs), [source primitives](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/source.rs).

Prepare generation before fetch. Compute a safe content version such as `sha256:<64 lowercase hexadecimal digits>` from the exact bounded fetched bytes. Do not claim semantic canonicalization or authenticity. Freeze parsed action input, target revision, idempotency, retry epoch, provenance, grant, and actor identity scope. Resuming an unknown request must not refetch changing content or silently prepare a newer generation. This is a proposed helper contract, not a new Runtime grant or durable ledger.

Receipt identity includes actor authority, principal kind, subject, target kind/id, operation tag or action name, and idempotency. Nonzero retry epoch adds a namespace. Permit fields are NOT part of identity. The fingerprint includes expected target revision, interpreted input, and complete `SourceProvenance`. Thus source/version/generation/field_origins differences can produce `IdentityMismatch` under the same identity. Dependency key/revision and permit expiry are NOT fingerprinted. [Identity](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/invocation.rs), [fingerprint/replay](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/replay.rs).

Current authority checks occur before receipt replay. A superseded or tombstoned dependency returns Conflict; expiry denies execution. Therefore an already committed unknown request can later become unreplayable through this grant. Do not interpret that rejection as proof of rollback. Renewing expiry or replacing a dependency requires explicit host reauthorization; receipt fingerprint compatibility alone does not grant authority. Replay also requires current and historical disclosure authorization. [Authority](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/execution/authority.rs), [command ordering](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/execution/command.rs).

Do not automatically map action input origins onto output fields. Actions can rename, compute, retain, add, or remove fields. Runtime validates origins against the complete final live object. The host/application must attest the complete output-origin map for this action contract. Runtime only checks coverage and permitted labels; it does not verify causal attribution. General partial ownership or mixed source origins need a separate explicit application contract. Source metadata inspection additionally requires `source_metadata_policy` and current disclosure authorization.

Invocation byte admission is private `check_size`; it counts serialized Invocation, actor identity, host stamp, and permit without allocating the serialized request. Default `Limits::command_bytes` is 16 KiB. No public generic Invocation stable-binding or size-check method was found. Public `Command<R>` converts into Invocation. This avoids private construction but does not expose ReloadTicket bindings. [Invocation](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/invocation.rs), [limits](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/execution/lifecycle.rs).

## Follow-up: parser suitability and precision

`rom_config::parse` accepts at most 65,536 bytes and 128 top-level fields. It requires a safe origin label of at most 64 ASCII alphanumeric/underscore/hyphen characters. JSON must have an object root. Its preliminary visitor rejects duplicate keys recursively and trailing input. Literal dotted JSON fields remain literal. Its origin map describes parsed top-level INPUT fields only. [Published parser](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom-config/src/parser.rs).

The pinned config dependency is exactly 0.15.27. Its JSON adapter tries `as_i64`, then `as_u64`, then `as_f64`. ROM converts I64/U64 directly back into JSON numbers. Integer tokens within signed/unsigned 64-bit range therefore avoid f64 conversion, including values above 2^53. Decimal/exponent forms and integers beyond those ranges can take f64 conversion; arbitrary numerical precision is not promised. [Exact config JSON source](https://raw.githubusercontent.com/rust-cli/config-rs/f14a0442345bd63e84638e37aa13daa383f0ba54/src/file/format/json.rs).

The published lockfile selects TOML `1.1.6+spec-1.1.0`. Its parser uses recursion limit 80 unless `unbounded` is enabled. This is a dependency feature guarantee, not a configurable rom-config depth parameter. Cargo feature unification can alter it; qualification must inspect the resolved features. JSON retains serde_json's default recursion guard unless explicitly disabled. A configurable tighter import depth needs explicit admission and cannot be claimed from a byte limit alone. [Exact TOML parser](https://raw.githubusercontent.com/toml-rs/toml/572c005d80cca5f7bd163805c2f33ba0a5207b6d/crates/toml/src/de/parser/mod.rs), [serde_json recursion API](https://docs.rs/serde_json/latest/serde_json/struct.Deserializer.html#method.disable_recursion_limit).

TOML forbids duplicate key definitions. The config adapter uses TOML's parsed table rather than merging documents. Integer conversion uses i64; values outside signed 64-bit range are rejected. TOML datetimes become strings. ROM rejects nonfinite floats. JSON and TOML are therefore not numerically identical import formats. [TOML specification](https://toml.io/en/v1.0.0), [exact config TOML adapter](https://github.com/rust-cli/config-rs/blob/f14a0442345bd63e84638e37aa13daa383f0ba54/src/file/format/toml.rs).

The public `rom::parse_json` is an alternative for generic JSON action input. It rejects duplicate keys at every depth and accepts scalar/array roots. Callers own byte bounds and root policy. Neither parser automatically makes parsed fields valid action input or proves output attribution. This review ran no precision, duplicate, nesting, replay, or unknown-outcome fixtures. [Public JSON parser](https://github.com/pmikstacki/ROM/blob/d7ef529040eec60dc869034c2d33130219db85fe/crates/rom/src/json.rs).
